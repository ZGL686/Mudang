# ADR-001：按完整对话提交并推送 GitHub

## 背景

用户明确要求：每次完整对话中有工程改动时，在工作完成后进行 Git 提交并推送到 GitHub。记忆系统与根目录 Agent 指引需要保留这一工作方式，避免后续会话遗漏。

## 决定

每次完成一轮包含工程文件改动的对话后，先检查仓库状态和差异，只提交本轮改动，创建一次语义清楚的提交，再推送当前分支到已配置的 GitHub remote。纯讨论且没有工程改动的对话不产生空提交。

用户于2026-10-03明确指定唯一目标为 `https://github.com/ZGL686/Mudang.git`。后续应核对remote与该地址一致；不能推送到其他仓库。GitHub元数据显示该仓库公开、大小为0、默认分支为 `main`；这不证明本地已完成关联或具备推送权限。

用户随后明确要求解决本地初始化和写入权限限制，已授权首次初始化、关联指定远程并推进首次导入；不再把初始化授权列为待办。若未来仓库状态异常，先核对现有.git和remote，避免在其他目录误建仓库。不得猜测远程地址、推送到其他仓库，或在失败时声称成功。

## 理由

用户希望每次完整交付都有远程版本记录。按轮提交能把一段对话对应到一个审阅单元；明确检查仓库和 remote 可避免混入无关改动或推到错误目标。

## 影响

- 有文件改动的交付需要在收尾阶段检查 Git 状态、审阅差异、提交并推送。
- 当前工作目录已初始化Git，分支为main，origin为用户指定地址；首次导入范围包括工程、素材、源文档、QA和wiki_memory，原始大ZIP及可重建缓存由.gitignore排除。
- 本机Git已通过Windows凭据管理器完成ZGL686设备登录，GitHub官方API核验该账号对目标仓库push:true。仓库级提交作者使用已核验的GitHub用户名及隐私noreply邮箱；令牌不写入源码、记忆或远程URL。
- GitHub连接器仍使用DewMysimple且push:false；常规提交推送使用本机Git。不要把连接器权限误当成本机Git权限，也无需为每次推送重新登录。
- 连接器权限和本机Git认证分别记录。首次提交与推送是否完成，以git日志、push结果和远端main哈希为准，不能仅凭登录或初始化成功判断。

## 验证方式

检查 git rev-parse --show-toplevel 成功，git remote -v 显示预期 GitHub remote，提交后 git status 干净且 push 成功。
